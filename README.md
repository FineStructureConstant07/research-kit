# Research Kit：通用研究体系 Agent 蓝图

> 从一场跨 4 个仓库、8 年数据、10 个方向的金融量化研究之旅中提炼。
> 那段旅程反复经历「强信号 → 假象」的翻案（beta/风格偏、流动性溢价、不可执行、秩相关假象、短窗口切窗），最终只找到一个经得起验证的策略。
> 本 Kit 把踩坑换来的方法论抽象为**不绑定金融**的通用研究体系，供任何数据驱动的调查项目直接复用。

---

## 1. 定位

本 Kit 回答一个问题：**如何组织一支（人或 Agent 的）研究团队，让「看着很真的结论」在落地前被充分证伪？**

它不规定用什么模型、什么数据、什么语言，只规定三件事：

1. **怎么想**：假设驱动、快速证伪、诚实标注（`AGENT.md`）。
2. **怎么分工**：层级化小组长制，父代理管方向、小组长管执行（`workflow.md`）。
3. **怎么算过关**：一套通用验证纪律清单，任何结论都要走完（`validation-checklist.md`）。

核心信条一句话：

> **任何一个「强信号」，只有扛过时间切分、混杂控制、真实执行约束与极端压测之后，才有资格被称为结论；扛不住，它只是一个假象。**

适用对象：

- 用 Agent（如 Claude/DeepSeek 等模型驱动的子代理）做研究编排的人：本 Kit 即「编排剧本」。
- 完全人工的小团队：把「小组长」替换为真人即可照常使用。
- 单干研究者：把清单当作自查标准，把模板当作给自己的任务书。

## 2. 适用场景

适用于一切「**有数据、有假设、有被证伪风险**」的调查项目：

| 领域 | 例子 |
|---|---|
| 金融/量化 | 因子有效性、策略回测、资产配置、风控规则 |
| 用户/产品 | 留存归因、A/B 结论复核、功能对指标的"真实"影响 |
| 运营/营销 | 渠道 ROI、活动效果、促销对长期用户价值的侵蚀 |
| 供应链/风控 | 延迟根因、损耗预测、异常模式是否可执行 |
| 生物/医药 | 生物标志物与疗效关联、差异表达分析的混杂控制 |
| 社会科学 | 政策效果评估、调查数据分析、因果推断的稳健性 |
| 体育/游戏 | 战术效果评估、选手/角色平衡性、版本改动影响 |
| 任何「从数据找因果/关联并要据以决策」的调查 | 统一适用 |

不适用场景：纯理论推演、无数据的头脑风暴、一次性快问快答。

**典型触发信号**（出现任一，即该引入本 Kit）：

```text
- 团队对一个「结论」有分歧，谁都说服不了谁；
- 上一个结论上线后翻车了，现在没人敢信下一个；
- 数据很多，但「靠谱结论」很少，产出全是 PPT 数据；
- 多个人/多个 Agent 并行研究，结果互相打架、口径不一。
```

## 4. 使用方法

### 方式 A：Agent 编排（推荐）

1. 把 `AGENT.md` 全文作为**研究经理 Agent** 的系统提示。
2. 研究经理在派发每个小组长时，从 `prompt-templates.md` 复制对应模板，替换 `{项目背景}` `{数据}` `{问题}` 占位符。
3. 验证环节强制要求小组长**逐条对照 `validation-checklist.md` 输出结论**，缺一条即打回。
4. 每个阶段结束，要求落盘文档（见 `AGENT.md` 产出清单）。
5. 全程关键节点人工抽查证据（不只看 Agent 的总结陈词）。

### 方式 B：人工团队使用

- 项目负责人 = 研究经理：只做方向决策与综合，不做具体执行。
- 每个方向任命一名小组长，按 `prompt-templates.md` 下达任务。
- 验收任何结论前，先过 `validation-checklist.md`，逐项打勾。
- 数据环节按 `data-pipeline.md` 落地。

### 方式 C：个人自查

- 把自己的研究结论逐条过 `validation-checklist.md` 的自查脚本；
- 用 `prompt-templates.md` 给自己派活（把「你」当小组长）。

### 最小启动步骤

```text
1. 写下第 1 个假设（越具体越好，能被数据证伪才算合格）
2. 派一名调研小组长：现有证据/数据口径/相关结论
3. 小样本快速验证 → 通过则全样本 → 不通过则改假设或放弃
4. 全样本通过后，按 validation-checklist 七条纪律逐条压测
5. 全部存活 → 落地；任何一条翻车 → 回到第 1 步
```

### 30 分钟非金融示例（用户留存）

```text
问题：夜间活跃用户是否留存更高？
假设：H1「过去 7 天夜间活跃的用户，30 天留存率显著更高」。
     证伪条件：剔除渠道混杂后差异消失，或分月看某几个月不成立。
调研：确认有 3 年行为日志，口径为「凌晨 0-6 点有任意一次会话」。
快速证伪：取 1 个月小样本，夜间组 vs 日间组留存差异显著 → 存活。
全样本：分月切分 36 个月 → 其中 4 个月差异不显著（纪律1 翻车）；
        控制渠道/机型/注册年份 → 差异缩小一半（纪律3 部分翻车）；
        结论降级为：「仅在下半年旺季成立，且渠道混杂未完全剔除」。
产出：待定，不落地；改写假设 H2 后重验。
```

这个例子展示了本 Kit 的完整闭环：**结论从「显著」被压成「待定」，这就是本 Kit 在正常工作。**

## 5. 与金融之旅的对应关系（供溯源）

| 本 Kit 的通用概念 | 金融之旅原经验 |
|---|---|
| 快速证伪 | 先小样本快速验证，再全样本 |
| 时间切分纪律 | 分年/分段的稳健性；警惕「单窗口/单段撑起」 |
| 混杂控制 | 剔除 beta/风格偏（中性化/回归残差） |
| 执行约束 | 流动性溢价、不可执行信号 |
| 压测 | 分年 + 极端尾部 + 保守成本，活下来才算真 |
| 防泄漏 | 预处理、参数、过滤全程对齐时点 |
| 诚实原则 | 结果不夸大，标注未验证假设与口径差异 |
| 层级化小组长制 | 父代理只做方向决策 + 综合，小组长可再派子代理 |
| 数据工程 | 增量回填 + 去重 + 自动备份 + 可续跑；密钥不入库 |

## 6. 常见误区（反模式）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 先找支持证据，后「验证」 | 假象被反复确认 | 先证伪（清单纪律 0） |
| 用全样本一次性结论 | 单窗口撑起 | 时间切分逐段看 |
| 只看绝对收益/提升 | 无基准的噪声 | 必须设对照/基准 |
| 纸面条件（零成本/无限容量） | 落地即亏 | 按真实执行约束压测 |
| 预处理用全样本统计量 | 未来泄漏，结论虚高 | 时点对齐，滚动处理 |
| 结果好看就收工 | 尾部一压就碎 | 极端尾部 + 保守假设 |
| 让小组长自由发挥无验收标准 | 产出无法验收、反复返工 | 派发即给验收标准 |
| 出错就换个说法再问 | 小组长迎合你 | 明确写错在哪，原样重派 |
| 结论只在聊天里，不落盘 | 遗忘、重复劳动、口径漂移 | 每阶段落盘文档 |

## 7. 术语表

| 术语 | 含义 |
|---|---|
| 研究经理 / 父代理 | 只做方向决策与综合的管理者，不执行细节 |
| 小组长 | 负责一个方向、一个问题的执行负责人，可再派子代理 |
| 快速证伪 | 先用小样本、低成本手段尝试推翻假设 |
| 中性化 / 回归残差 | 剔除混杂因素的方法（通用版：分层、匹配、残差化） |
| 水位线 | 增量管线记录「已成功拉取位置」的标记 |
| 可续跑 | 中断后从断点继续、不重复不遗漏的能力 |
| 翻车 | 假设/结论在验证中死亡 |
| 待定 | 结论未通过全部纪律时的唯一合法状态 |

## 8. FAQ

**Q：我是非金融项目，这些纪律会不会太严？**
A：严的不是纪律，是「结论」这个词的门槛。你仍然可以先行动（快速决策不受限），但凡是写进报告、要别人信、要据此长期投入的结论，就该过这套纪律。日常小决策可以只走快速证伪。

**Q：一定要用多 Agent 吗？**
A：不。层级化是管理结构，人可以替代任何 Agent。单人也行（见方式 C）。

**Q：每个结论都要七条全过吗？**
A：要被称为「结论」就必须全过。过不了的，降级为「待定」或「观察」，照样可以有限行动，但必须明说。

**Q：这套东西自己会不会被证伪？**
A：它的核心主张（切分、对照、混杂、执行约束、防泄漏、压测）在金融之旅上被反复验证有效。欢迎在你的项目里压测它：如果某条纪律在你的领域确实无效，请带着案例来改 Kit（见维护约定）。

**Q：多久能见效？**
A：第一个项目就能见效——通常第一个假设在七条纪律下从「成立」降为「待定」，这就是见效（拦住假象）。真正形成团队习惯需要 2-3 个项目的复盘沉淀。

（完）

## 9. 维护约定

- 本 Kit 是**活文档**：每次研究项目结束后，把新的翻车案例补进 `validation-checklist.md`。
- 规则条目宁少勿滥：每加一条纪律，必须附带一个真实案例支撑。
- 占位符模板保持最小化：模板里只留「必须填」的占位符，其余交由小组长发挥。
- 版本演进建议：先整体沿用 2-3 个项目，再据实战裁剪，避免一开始就魔改。

## 10. 与其他方法论的关系

| 方法论 | 关系 |
|---|---|
| 科学方法（假设-实验-证伪） | 本 Kit 是其可操作化：把「可证伪性」变成清单与流程 |
| CRISP-DM（数据挖掘标准流程） | 本 Kit 覆盖其「业务理解→评估→部署」，额外强制验证纪律与诚实原则 |
| A/B 实验体系 | 纪律 1/2/3/5 与实验规范同源；本 Kit 扩展到「无随机对照可用」的研究 |
| 因果推断（DID/RDD/IV） | 是纪律 2/3 的工具箱，不是替代品 |
| MLOps/DataOps | 数据工程铁律（`data-pipeline.md`）与之对齐，可无缝嫁接 |

本 Kit 不发明新理论，**只把已知的正确做法变成必须执行的纪律**。

## 11. 引入组织的落地建议

- **先用一个小项目试点**（2-4 周、一个假设），跑通「假设→验证→待定/成立」闭环，再推广。
- **先改验收，再改流程**：在现有评审会上引入 `validation-checklist.md` 作为结论的通过条件，阻力最小。
- **把翻车案例当资产**：每季度把「结论被证伪」的案例补进 Kit，团队共识随之建立。
- **配套一个名词约定**：全团队统一使用「待定 / 假象 / 成立」三个词，禁用「基本成立」「大概率」。
- 落地顺序建议：`validation-checklist.md` → `prompt-templates.md` → `workflow.md` → `data-pipeline.md`。

## 12. 「这套 Kit 是否在起作用」的判断标准

出现以下迹象，说明 Kit 在正常工作（哪怕结果不「好看」）：

```text
- 结论数量变少、但每个都带着边界与局限；
- 团队开始主动报告「翻车」，而不是等别人发现；
- 「待定」成为正常词汇，不再被视为失败；
- 复盘时能精确说出某个假象死于哪条纪律；
- 上线后的意外结果变少，且每次意外都能追溯到未验证假设清单。
```

出现以下迹象，说明 Kit 被架空了：

```text
- 验证报告七条全「通过」但没有任何一条附证据；
- 结论先在会上宣布，清单事后补填；
- 「未做」的理由总是「时间不够」，且没有补验计划；
- 小组长汇报永远四段式，但「局限」永远是空话。
```

## 13. 一个完整的里程碑示例（两周，非金融）

```text
Day 1   ：立项 → hypotheses.md（3 个假设 + 证伪条件）→ 派调研小组长
Day 2   ：data-notes.md 落盘；H1/H2 进快速证伪（验证小组长）
Day 3-4 ：小样本结果：H1 存活、H2 已死（渠道混杂）、H3 数据不足挂起
Day 5-9 ：H1 全样本验证：分周切分、渠道分层、保守成本、泄漏审计、尾部压测
Day 10  ：终审：七条中 6 过 1 待（执行约束数据未齐）→ H1 标「待定」
Day 11  ：补执行约束数据 → 重验 → 成立（带边界：仅旺季/安卓端）
Day 12-13：落地小组长：实验方案 + 监控看板口径 + 边界说明
Day 14  ：向上层四段式汇报 + journal.md 全程记录 + 复盘补案例
```

## 14. 速查卡（打印贴在墙上）

```text
研究四问：
  1. 这个假设能被数据证伪吗？写不出证伪条件 → 不派发。
  2. 小样本翻车了吗？翻了 → 放弃或改写，不进全样本。
  3. 七条纪律逐条过了吗？缺一条 → 结论只能是「待定」。
  4. 落地时边界带上了吗？没带 → 不准交付。

七条纪律（口诀：证伪、切分、对照、混杂、约束、泄漏、压测）
  0 先证伪  1 时间切分  2 基准对照  3 混杂控制
  4 执行约束  5 防泄漏  6 极端压测

三个状态词：待定 / 假象 / 成立（禁用「基本成立」「大概率」）
四段式汇报：结论 + 证据 + 局限 + 一句话建议
数据五铁律：增量、去重、备份、可续跑、密钥不入库
组织口诀：父代理管方向与综合，小组长管执行，出错写明原因原样重派，两次失败换人。
```
